# Power of the Wilds (Wild Heart lv14) sheet row is an inert control — Lion/Falcon/Ram can never be chosen

## Summary
`Power of the Wilds:` renders as a clickable bonus-action row on a Path of the Wild Heart Barbarian's sheet and its React `onClick` is bound (`() => handleAutomationClick(specialAction)`), but clicking produces **zero observable delta** — no chooser modal, no popup, no log row, no state write. The feature's data declares full automation (`{type:'combat_stance', effect:'power_of_wilds_option', options:[Falcon, Lion, Ram]}` in `public/data/2024/classes.json`), and the CONSUMER side of every option exists (Ram prone rider `handlePlainDamage.js:312`, Lion disadvantage aura `lionAuraUtils.js`, Falcon fly-speed strip `combatStanceHandler` flight seam) — but no Lion/Falcon/Ram buff can ever legitimately enter play because the producer UI never opens the picker.

## Steps to reproduce
1. In `test-campaign`, open the DraconicDragon sheet → **Edit** → wizard step "6 Subclass / Major" → select **Path of the Wild Heart** → ✓Save (disk-verify `class.subclass.name` = `Path of the Wild Heart` via `GET /api/campaigns/test-campaign/DraconicDragon.json`).
2. Re-open his sheet. Click **Rage:** → Rage activates (popup + `Rage` stance buff stamped — this sibling works).
3. Click **Rage of the Wilds:** → Bear/Eagle/Wolf chooser modal (`.sp-modal`) opens with an `Activate Rage of the Wilds` button (this sibling works; pick Wolf, activate → `Rage of the Wilds` buff stamped, `Selected Wolf wild form` logged).
4. Click **Power of the Wilds:** → observe. Nothing happens. Retry 2–3 more times after clearing all popups (fresh `b.clickable` rect, trusted mouse + synthetic click both probed): still nothing — no Falcon/Lion/Ram modal, no popup, log entry count unchanged, `change-data` DraconicDragon bucket unchanged, console silent.

## Expected behavior
Per `classes.json` Power of the Wilds (lv14, automation options authored), the click should open the same CombatStance chooser as Rage of the Wilds offering Falcon/Lion/Ram, and activating should stamp an `activeBuffs` entry carrying `optionName: 'Falcon'|'Lion'|'Ram'` — the shape `lionAuraUtils.lionBuffFor` (`optionName === 'Lion'`), the Ram rider (`handlePlainDamage.js:312`), and the Falcon fly-speed lane already read. Note this is the ONLY app-wide producer for the Lion aura — the two Lion-aura fix/verify runs (76fa0f578, CI 11-03) had to hand-stamp the buff via API because no UI can create it.

## Actual behavior
Zero delta from any Power of the Wilds click (verified twice this session incl. once with fully clean popup state; log count constant, modal query for /Falcon|Lion|Ram/ empty, zero console errors). Contrast step 2/3 siblings firing on first click.

## Likely location
Confident it's in the sheet special-action dispatch, NOT the stance handler: `combatStanceHandler.handle()` line ~89 returns the `combatStance` modal for ANY action with `auto.options.length > 0`, so if the folded action reached it the modal would open. The break is one layer up — `CharSpecialActions.jsx:805-812 handleAutomationClick` (`if (!result) return;` = the silent-drop surface) — most likely because the feature is collected into the Special grid WITHOUT its `automation` dict (executor finds no `automation.type` → returns undefined) or `openChoicePromptIfNeeded` (line 810) swallows it. Start by reading `openChoicePromptIfNeeded` + the automationCollector bucket routing for effect `power_of_wilds_option` (grep-zero in `src/` app-wide: only `public/data/2024/classes.json:1009` mentions it) and comparing the folded `specialAction` object for Power of the Wilds vs Rage of the Wilds (the latter effect key IS referenced by routing/tests).

## Suggested fix
First diagnostic: fiber/props-dump the Power of the Wilds specialAction at click time to confirm whether `action.automation` is present. If absent → collector routing fix (make the lv14 feature fold its combat_stance automation like the lv3 twin). If present → trace `openChoicePromptIfNeeded`/`delegateAutomationClick` for an early return and let the result reach `dispatchModalResult('combatStance', …)`. Regression: live-click Falcon/Lion/Ram → stamp shape byte-matches `lionAuraUtils`/Ram rider/Falcon flight consumers.

## Severity
Broken feature — an entire lv14 subclass feature (3 options incl. the app's only Lion disadvantage aura) is unreachable through legitimate UI while its consumers wait for a buff nothing can produce; the row's clickability actively misleads (users see a control that does nothing).

## Resolution
FIXED 2026-11-03 — the row DID carry its `automation` dict and `executeHandler` DID reach `combatStanceHandler.handle()`, which correctly returned `{type:'modal', modalName:'combatStance'}`. The silent drop is the grid's own dispatch table: `CharSpecialActions.jsx dispatchModalResult` matched the modalName against neither `MODAL_DISPATCH` (the grid's local setter map) nor `CHOICE_MODAL_EVENTS` (the window-event bridge into the CharActions tree) — an unmatched modalName falls out of the function with zero log/popup/console, exactly the observed face. The lv3 twin escapes this because its `casting_time:"1 bonus action"` makes `rules.js categorizeByCastingTime` place it on the Bonus Actions panel instead, whose `useCharActionsAutomation.modalMap` HAS `combatStance`; Power of the Wilds carries `casting_time:"passive"` → Special grid → dead table. A latent second defect waited behind it: every Wild Heart lane gate in `combatStanceHandler` keyed on `action.name === 'Rage of the Wilds'`, so even with the modal open, Power of the Wilds would have silently consumed a rage USE (default `ragePoints` pool), logged NOTHING, and stripped itself on re-click.

**Changes:**
- `src/components/char-sheet/CharSpecialActions.jsx` — `CHOICE_MODAL_EVENTS` gains `combatStance: 'combat-stance-modal-show'` (the established MN-002 bridge pattern for CharActions-tree modals).
- `src/components/char-sheet/useCharActionsEventListeners.js` — new symmetric listener: `combat-stance-modal-show` → `setModalState({ combatStanceModal: event.detail })`, mirroring `useCharActionsAutomation`'s working lv3 simpleModal lane; the tree's existing `CharActionModals` CombatStanceModal mount (with its `buffs-updated` close sweep) is reused untouched.
- `src/services/automation/handlers/combat/combatStanceHandler.js` — one `WILD_HEART_STANCE_NAMES = ['Rage of the Wilds', 'Power of the Wilds']` helper + `isWildHeartStance(action)` now drives all four gates: (1) re-click while active re-opens the chooser instead of silently stripping, (2) `handle()` routes straight to the chooser modal, (3) activation requires an active Rage and consumes NO rage use (`consumeStanceResource` wild-heart branch), (4) the selection log. Refusal copy and log `automationType` generalized to `${action.name}` / `action.name` — both lv3 pins stay byte-identical (`'Rage of the Wilds requires Rage to be active.'`, `automationType:'Rage of the Wilds'` + `Selected Wolf wild form`); lv14 logs `automation/Power of the Wilds/Selected Lion wild form`.
- `src/services/automation/handlers/combat/combatStanceHandler.power-of-the-wilds.test.js` (NEW, 8 pins) — chooser modal routing, re-open-not-strip while active, action-named Rage prerequisite refusal, zero ragePoints deduction, and consumer byte-pins: Lion `{name:'Power of the Wilds',effect:'power_of_wilds_option',duration:'while_raging',optionName:'Lion',range:'5 ft'}` (lionAuraUtils `optionName==='Lion'` + `range`), Ram `optionName:'Ram'` (contextBuilder-sync:149 gate / handlePlainDamage rider), Falcon `flySpeed:'speed'`+`noArmor:true` generic-fly buff (charSummaryCalc `isGenericFlyBuff`, effect absent from `NON_GENERIC_FLY_EFFECTS`) incl. the armor-blocked face (Berserker's heavy armor is the app-wide `isWearingArmor` gate residual).
- `src/components/char-sheet/CharActions.events.test.jsx` — consumer-side row added to the modal-show passthrough table (`combat-stance-modal-show` → `combatStanceModal`).
- `src/components/char-sheet/CharSpecialActions.modals.test.jsx` — emit-side pin: clicking a combat_stance grid row whose handler returns the modal result dispatches exactly one `combat-stance-modal-show` CustomEvent carrying the payload.

Dual-ruleset: Path of the Wild Heart exists only in `public/data/2024/classes.json`; the fixed chain (grid bridge + listener + combatStanceHandler) is ruleset-shared — no 5e twin to mirror.
