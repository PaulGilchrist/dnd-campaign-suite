## Known Quirks & Gotchas (live run C)

- React state-class reads (`creature-circle dragging`) and ctxmenu rendering are NOT same-tick synchronous after a dispatched event — await ≥150ms in the evaluate before reading.
- SVG ctxmenu has no `.click()`; only `dispatchEvent(new MouseEvent('click',{bubbles:true}))`. A `browser_click` on the menu-option ref closed the menu WITHOUT opening confirm once (flaky lane — dispatch lane is the reliable one).
- Playwright `:text-is` locator default 30s timeout = pseudo-hang when the panel unmounts mid-flow (arrival) — ALWAYS pass explicit `click({timeout:5000})` and re-probe state after any TimeoutError (a TimeoutError mid-loop may leave partial advances done).
- `about:blank` fetch HANGS the Code Mode runtime unkillably (no AbortSignal/setTimeout there) — only fetch `/api/...` endpoints from `execute`.
- Seeded `travel-dayExhausted` POST did NOT render the exhausted banner in an already-open editor (hook state didn't apply the echo) — external seeds prove click-guards, not renders.
- Weather re-rolls silently on travel-tool mount; seeded map weather won't survive a tool press.
- `weatherService.test.js` fog mock `budgetMod:0.75` is STALE vs production (1.0) — storm is the 0.75 one; trust source table, not mocks.
- Console-error hygiene: a wrong-probe URL (nested `/char/key`) shows as an app 404 in console — attribute carefully.
- First open after restoring `zoom:1` self-heals to MIN_ZOOM 2 (one legit PUT, canonical now).
- From prior runs (still live): final-hex travel advance logs ONE `arrived` row; score-cell clicks pop result modal; one SSE per campaign; reload deselects campaign; `performance.getEntriesByType` under-captures PUTs (judge by disk GET); `elementFromPoint` className on SVG nodes serializes `{}`.
