## Key UI Patterns & Reliable Selectors (run BC additions)

- **Sidebar vs board collision:** a plain `getByRole('button',{name:'<CharName>',exact:true})` strict-violates on a mounted Initiative board (the card `div.avatar-wrapper[role=button]` carries the same name) — scope sidebar nav to `page.locator('#sidebar-nav button', {hasText: /^<CharName>$/})`.
- **Rename row controls:** never CSS-attribute-match the quote-embedding aria-labels; use `getByRole('button',{name:'Rename "BC Rename Sandbox"',exact:true})` for buttons and `input[placeholder="Rename to…"]` (exact placeholder, ellipsis char U+2026) for the input. NEVER bare `getByRole('button',{name:/^Rename /}).first()` — that's what renamed battle-arena (see Quirks).
- **Victory chrome:** `.victory-banner` root, `.victory-line` copy rows, dismiss by `getByRole('button',{name:'Dismiss victory banner'})`; same-context retirement rides the `storage` event (jsdom pins: `new window.StorageEvent('storage',{key})` — omit `storageArea`).
- **Refusal popup buttons:** `.popup-modal` buttons `[Arm a target, Done]`; focus oracle = `document.activeElement.getAttribute('aria-label') === "<Attacker> target"` with `tagName === 'SELECT'`.
- **Arm via focused select:** `page.selectOption('select[aria-label="<Name> target"]', '<Target>')` — trusted change writes `targetName` through the normal lane.
- **API lanes used clean:** `POST /api/campaigns/:c/maps`, `PUT …/maps/<slug>/rename {newName}` (GM-only, plain-English 400s), `DELETE …/maps/<slug>` (+ghost GET 404), scoped `PATCH /combatSummary {value:{creatures:[{name,targetName}]}}`, admin clears `POST /api/campaigns/:c/admin/clear-change-data|clear-log` (localhost origin — a curl from localhost IS GM origin; closed-tab single-pass verified `{}`/`[]` after ~12 s).

## Quirks / Gotchas (run BC)

- **Rename is not byte-neutral on legacy docs (COST A SCARE):** a sloppy `.first()` locator armed the battle-arena row; the Confirm leg renamed the owner fixture. The flip-back rename restored name/displayName but NOT the md5 pin (`94fcd0bf`→`4abc0ec7`): the rename route sets `mapData.name`/`displayName` and re-serializes `JSON.stringify(mapData,null,2)` — battle-arena.json's original bytes CARRIED NO `name` KEY (legacy shape; the list builder derives it), so the injected key survives the flip-flop permanently. Recovery: `cp dist/campaigns/test-campaign/maps/battle-arena.json public/…` (twin md5 == pin). LAW: ride rename ONLY on sandbox docs; the dist twin is the sanctioned byte restore.
- **Cross-row blur-commit:** with a rename editor armed, clicking ANY other row button blurs→commits the pending value (silent, by the old blur law); the consequent list re-render can silently UNMOUNT the editor that same click just armed (Cancel locator then times out). Both backlogged.
- **Storage event = same-context only:** the sibling-tab victory retirement proof REQUIRES both tabs in ONE browser context (`context().newPage()` shares localStorage); a `browser.newContext()` partition never receives the event and correctly keeps its own banner.
- Refusal log filter: `automationType:'longsword_refused'` — the description is lowercase `no attack rolled.`; a `No attack rolled` case-sensitive filter false-negatives.
- Extra-Attack chain face: after Swing 1 MISS, `Done` advances to Swing 2 of 2 with a FRESH roll staged (crit face carries `Done`+`Cancel attack`); the kill commit lands exactly one `hp_change`.
- A LAN tab's sidebar sheet click mutates that device's target-arm ownership (`localCharacterName` follows sidebar selection) — design D2, but harnesses must re-census which card is armable after any visitor sheet visit.
